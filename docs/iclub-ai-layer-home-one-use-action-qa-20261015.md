# iClub AI Layer v2.1 — §108: одноразовое подтверждение Home (QA-only)

**Дата:** 2026-10-15. **Статус:** TEST-ONLY, Global AI production/beta NO-GO.
**Ограничения:** без новой Supabase-ветки, live RPC, Vercel deploy, платных моделей и изменений прогресса.

## Что решаем

Подписанная Home-рекомендация (§104–107) подтверждает только момент выдачи. Она не должна сама считаться разрешением выполнить действие позже — права на предмет, исходные данные, источник или текущий экран могут измениться. Повторное использование ранее выданного разрешения также запрещено.

## Реализация

В `qa/ai-layer-v21-p6-home-action-handoff.cjs` реализованы две независимые операции в **локальном синтетическом** HTTP-контуре:

- **Issue:** только после подписанного плана, проверки полного приоритета и заключительного Home authority gate создаётся криптографически случайный 192-битный непрозрачный `handoffToken`. Наружу токен не раскрывает user/evidence IDs, plan, grades, ответы и source hashes. В одной специальной таблице временной PostgreSQL хранится только SHA-256 токена, владелец, contextHandle, локаль, screen revision, срок, неизменённый канонический подписанный план и список разрешённых вариантов. Таблица `private.iclub_ai_v21_home_action_handoffs_scratch` существует исключительно в одноразовом QA.
- **Confirm:** браузер возвращает токен, `contextHandle`, `locale`, `actionCode` и `subjectKey`. Личность вычисляется исключительно из серверной (синтетической) авторизации, а не из параметров. Сервер проверяет HMAC оригинального плана, владельца, язык, время и членство выбранного действия в выданном полном наборе. Затем **одним SQL statement** одновременно сверяет актуальный Home/предмет/тариф/результаты/источники через §107 MVCC CTE и атомарно переводит ровно одну запись токена из `consumed_at IS NULL` в использованное состояние. Повтор, чужой token, другие locale/subject/action и отозванные права возвращают отказ.

Технический ответ `qa_handoff_confirmed` **не означает переход к учебному экрану**. Он содержит `reviewOnly:true, releaseAllowed:false, navigationExecuted:false, progressChanged:false`. Реальные Practice, Tour, сертификаты, начисления, данные подписки и localStorage не затрагиваются.

В `qa/ai-layer-v21-p6-home-pg-http-gateway.cjs` появились локальные `/qa/home/next` (только synthetic token issue) и `/qa/home/confirm` (только synthetic claim). Они доступны лишь временной loopback-сессии GitHub Actions и не должны попадать на production.

## Проверки

`qa/ai-layer-v21-p6-home-action-handoff.test.cjs` проверяет структуру одноразового разрешения и отказ при нарушении подписанного плана. В `qa/ai-layer-v21-p6-home-pg-http.test.cjs` проверяются чужой user, подмена предмета/действия/языка/context, попытка добавить клиентский `userId`, повторное использование, отзыв source rights после выдачи и отсутствие изменения учебного прогресса.

`qa/ai-layer-v21-p6-home-action-race.cjs` запускает **два независимых worker thread**, которые одновременно используют отдельные `psql`-процессы для захвата одной записи из отдельной одноразовой PostgreSQL. Только один запрос может подтвердить token; второй должен получить отказ. Сразу после проверяется отсутствие изменений в Practice.

## Граница выпуска

Единый SQL MVCC read/claim даёт атомарность захвата *только искусственного одноразового разрешения*. Это **не** внедрение живой транзакционной авторизации в Supabase и не полноценный пользовательский переход. Отзыв после завершённого SQL claim или до последующего реального действия требует **новой проверки в той же реальной DB-транзакции, что и само действие**, и отдельного review миграций/permissions. Реальные академические права и source-governance publication остаются неутверждёнными.

**Подтверждённый CI:** [GitHub Actions #319](https://github.com/jteshaboev1984-ops/iClub_APP/actions/runs/38689905828) — полный **GREEN**: **649/649 Node**, **14/14 независимых PG scratch suites**, native Chromium RU/UZ/EN включая `HOME_ACTION_CHROME_CONFIRM_GREEN` для каждого языка; реальный localhost HTTP→PG authority gate; отдельный `HOME_ACTION_TWO_WORKERS_GREEN`: два независимых psql-процесса, одно подтверждение и один блокированный повтор, без изменения Practice. Deno, старые race-проверки и контроль защищённых файлов также GREEN. 

Синтетический UI показывает подтверждение без академических изменений и без навигации. Он не является действующим приложением или разрешённым бета-релизом. Временный PR QA→QA закрывается без слияния в main.
