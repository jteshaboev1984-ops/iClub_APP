# iClub AI Layer §107 — single read-only PostgreSQL Home authority snapshot

**Дата:** 2026-10-15. **Режим:** только QA, disposable PostgreSQL, без новой Supabase-ветки и без запросов к пользовательским данным.

## Почему потребовался новый этап

Даже несколько повторных серверных проверок могут увидеть разные состояния при конкурентном обновлении: выбранный предмет, тариф, редакционное право или завершённость попытки меняются между `await`. Поэтому второй независимый контроль основан на одном последнем SQL-операторе `SELECT`. Он использует один MVCC snapshot PostgreSQL, а не соединяет ответы раздельных запросов.

## Что реализовано

`qa/sql_drafts/iclub_ai_v21_home_atomic_delivery_READ_ONLY.sql`:
- принимает строго подтверждённые server-owner UUID, Home handle, screen revision, срок действия и массив минимальных подписанных действий;
- **одним SELECT** повторно проверяет server-owned Home screen/context, expiry, глобальное отключение AI и защищённый экзамен;
- читает независимый server-scan текущих трёх типов действий и требует точного совпадения полного набора кандидатов с подписанным планом, включая priority/tie;
- сверяет коммерческий режим `enforced`, resolved subscription с `ai_generation_entitled=true`, отдельное QA-only разрешение функции, `study_selected`/`competitive_selected`, режим `user_subjects`, активность предмета;
- заново проверяет завершённую Practice с ошибкой, официальный истёкший Tour с разрешённой завершённой попыткой либо подтверждённый активный предмет;
- сверяет для каждого действия локально синтетический source release с RU/UZ/EN, флагами rights/content, отсутствием revocation, source hash/version;
- ограничивает исполнение БД именем `iclub_ai_v21_scratch_*`. В данном тесте подключение к PostgreSQL возможно только по loopback с синтетическим паролем.
- не пишет в БД, не запускает provider, не читает/не изменяет реальные записи учеников.

`qa/ai-layer-v21-p6-home-pg-http-gateway.cjs` передаёт разрешённые HMAC-поля в read-only query только после проверки типов, UUID, источника и допустимых действий. `qa/ai-layer-v21-p6-home-delivery-gate.cjs` отказывает при отсутствии результата `true` от последнего SQL-снимка; это последнее `await` перед возвратом только безопасного HTTP-ответа.

`qa/ai-layer-v21-p6-home-pg-http.test.cjs` имеет дополнительные детерминированные QA-хуки для отзыва source rights, тарифа или screen revision **прямо перед** SQL snapshot. Эти хуки доступны только искусственной localhost-демонстрации и не являются пользовательской функцией.

## Ограничения

- MVCC-оператор читает один непротиворечивый момент **временной тестовой БД**. Это не `SERIALIZABLE` транзакция с блокировками и не защита от отзыва, произошедшего после SQL-оператора или после выдачи HTTP. При будущем реальном действии/переходе нужен отдельный серверный authorization check в той же транзакции, что и само действие.
- Проверяемая схема коммерческих таблиц является source-audited mirror. Feature gate, публикации источников и учебные права в тестах **синтетические**; они не создают продуктовые права, платный баланс или лицензии.
- Нельзя переносить эту SQL-схему на действующую Supabase или объявлять продукт beta-ready.
- Vercel SSO Preview остаётся отдельной статической демонстрацией; локальный HTTP endpoint не развёрнут вне GitHub Actions.

**Global AI remains OFF / NO-GO.** Результат завершающего CI с last-moment revocation фиксируется отдельно после фактического прогона.
