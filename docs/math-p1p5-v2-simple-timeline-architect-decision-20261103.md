# Mathematics P1/P5 — решение архитектора: одна временная линия

**Дата:** 03.11.2026. **Преимущество:** простая, читаемая учеником схема вместо показа технических моделей и непонятных состояний. **Приоритет:** это актуальное продуктовое решение для Package 2 и планирования Package 3; при расхождении с более ранними сложными предложениями применять этот документ.

## Что видит ученик

**Начало подготовки → Сегодня → Дата своего экзамена.**

На сегодняшний день отдельно для P1 и P5 показываем **всю программу**, **подтверждённо освоенную часть**, **часть, где задания уже решались, но освоение ещё не подтверждено**, и **ещё не проверенную часть**. Остаток = вся программа − объективно подтверждённая часть. Ошибки используются для определения статуса навыка, а не умножения общего времени за каждый неверный ответ.

Далее простая последовательность: **сколько осталось → сколько времени потребуется → хватает ли времени до экзамена**. Пересчитываем после достоверного нового результата; ученик сам выбирает часы, расписание автоматически не меняем. Периоды и планы P1/P5 разные, но недельный бюджет Mathematics — общий.

## Откуда брать часы

**Не путать две цифры.** Количество часов, которое ученик сам выделил до экзамена, можно вычислить сразу: его выбранные часы Mathematics в неделю × оставшиеся календарные недели. Это **доступные часы**, не доказанное время, необходимое для изучения.

Для второй цифры — **сколько реально потребуется, чтобы освоить оставшееся** — нужна подтверждённая скорость освоения (сколько активных учебных часов требовалось при сопоставимом исходном уровне для освоения уже завершённого материала). Тогда формула приблизительной персональной оценки: **оставшееся содержание × проверенная средняя трудоёмкость сопоставимого освоенного содержания**. Для разных навыков допустима различная сложность, но она не должна превращаться в 486 настроек для ученика. При отсутствии достоверной скорости — честный статус «оценка времени пока недоступна», а не выдуманные часы. Без наблюдений нельзя считать посещение страницы, минуты таймера вопроса или календарное время реальным временем обучения.

Одна исходная граница — **начало/регистрация в Exam Prep**, вторая — **сегодня**, третья — **выбранная учеником дата каждого экзамена**. Если даты нет, не придумывать её, а предложить ученику указать её. Не обнулять ранее сохранённый прогресс.

## Фактически проверенные ограничения текущей базы

SELECT-only production audit 03.11.2026: среди 120 Exam Prep profiles у всех указана недельная Mathematics-доступность, но в таблице подтверждённых индивидуальных P1/P5 экзаменационных назначений **0 записей**. По строгой формуле текущего движка для P1 всего **одна** запись с объективно подтверждённым охватом навыка среди 4 590 skill-state записей, для P5 **ноль** среди 2 484. Это не означает, что ученики ничего не знают: это означает, что платформа пока почти не имеет достаточного *подтверждённого* покрытия для индивидуального вывода освоения и средней скорости. До накопления объективных данных **не выдавать точную оценку необходимого времени**.

## Что требуется от приложения

Использовать уже существующие серверные результаты по 81 навыку и выбранные даты экзаменов. Новый компактный read-only owner API в draft PR #470 показывает одну временную линию для P1/P5 и три цифры статуса, а также доступные часы, если выбрана дата экзамена. Не добавлять новые учебные этапы, ежедневные уведомления, квоты, автосбросы, самостоятельные письменные оценки, автоматические изменения времени и дополнительные обязательные настройки.

Академические технические исследования и реестры из P2-10/11/12 **не выводить на экран и не превращать в обязательные продуктовые этапы**. Они остаются внутренним техническим архивом только для возможного будущего улучшения точности расчёта. Они не препятствуют простому отображению линии прогресса; запрещено лишь выдавать недоказанное время как точную оценку.
