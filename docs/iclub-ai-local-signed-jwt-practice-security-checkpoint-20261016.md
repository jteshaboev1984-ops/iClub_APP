# iClub AI v2.1 — cryptographically signed identity in local Practice QA

**Date:** 16 October 2026
**Status:** GREEN in isolated synthetic QA; **real Supabase Auth and user rollout NOT approved**.
**Branch:** `qa/iclub-ai-layer-v21-20261012` (never `main`).

## Actual improvement

Previous disposable HTTP-to-PostgreSQL tests mapped plain strings like
`qa-local-user-a` to student identities. This exercised the database
owner checks but **did not** test a cryptographic signature.

Now the same existing `/context` flow uses an **actual HMAC-SHA256
signed JWT** generated by a fresh 32-byte random key for each local test run:

1. The browser-equivalent HTTP request carries the signed synthetic JWT.
2. The disposable local Auth endpoint checks the signature, exact `HS256`
   header, audience, issuer, authenticated role, subject UUID and issuance /
   validity / expiry times.
3. Only after that signed Auth response does the unchanged
   `createSupabaseServices.authenticate` derive the server-side user ID.
4. The existing `resolvePracticeV4` action invokes the service-role-only
   *synthetic/disposable* PostgreSQL function and matches one owned finalized
   V4 session and exactly one answered question.
5. Active assessment, revoked enrollment, disabled runtime, unauthorized
   source publication and absent independent Practice context mint continue
   to refuse; the authorized selector grants **no** AI answer or grade.

### Negative security tests

- Different test-run signature key, tampered claims/signature and unsigned
  identity strings are denied.
- Expired JWTs, future `nbf`/issuance, wrong issuer/audience, elevated
  `service_role` or anonymous role are denied.
- Signed learner B cannot read learner A's attempt or inject client `userId`.
- Direct learner invocation of the privileged resolver RPC is denied.
- No browser/service-key leakage and no academic-data mutation are permitted.

## QA components changed

- `qa/ai-v21-local-signed-auth.cjs`: ephemeral local HS256 signature and
  strict validator; guarded by `CI=true` and `ICLUB_QA_ALLOW_RESOLVER=synthetic-only`.
- `qa/ai-v21-local-signed-auth.test.cjs`: positive/negative crypto tests.
- `qa/ai-v21-practice-resolver-http-pg.cjs`: real signature check at the
  disposable HTTP Auth endpoint. The generated keys/tokens exist only inside
  the ephemeral GitHub Actions job; never sent to Preview or the production app.
- `qa/edge_v21/practice_resolver_real_pg_http_test.ts`: 8 actual localhost
  HTTP-to-PostgreSQL tests, including signature/claims denial matrix.
- `.github/workflows/iclub-ai-real-preview-qa.yml`: mandatory crypto QA
  tests and original browser/mapping regressions.
