# Mathematics P1/P5 Stage C — восстановление таймера Timed/Paper

**Подготовлено:** 2026-11-04. **Ветка:** \`fix/math-p1p5-stage-c-timed-session-countdown-20261104\`. Независимо от завершённого P2-17 (недельный бюджет). Включение на production не разрешено.

## Установленный дефект

В read-only проверке production \`public.get_exam_prep_session_safe_v1(uuid,text)\` возвращает данные сессии без \`timing_contract\`. В первоначальной реализации 20260904174000 это поле было; последующие 20260911141111 и 20260916095500 полностью переопределяли функцию и убрали его. Клиент \`exam-prep-live.js\` ожидает \`session.timing_contract.deadline_at\` для обратного отсчёта и автоматического завершения. При отсутствии поля таймер на экране не запускается. Нельзя делать из этого вывода, что сервер принимает просроченные ответы: серверные ограничения не менялись.

## Точечное исправление

1. **Переопределение ответа существующей функции**: новая миграция \`20261104080000_exam_prep_stage_c_timed_session_clock_restore_v1.sql\` сохраняет все существующие проверки владельца, формирование элементов и правила сокрытия правильности. Добавляет только для Timed и Paper пять ключей: \`deadline_at\`, \`time_limit_sec\`, \`strict_timing\`, \`attempt_kind\`, \`server_now\`. Для остальных типов сессий JSON \`null\`. Никаких полей внутренней оценки, \`comparability_key\`, \`marks_available\` и ключей правильных ответов наружу не передаётся. SQL не изменяет строки базы; если сигнатура/якорь функции поменялись — прекращает миграцию без частичного применения. Повторное применение идемпотентно.
2. **Браузерный расчёт**: при каждом открытии Timed/Paper сверить время браузера с \`server_now\` и показывать время до серверного \`deadline_at\`. Не создавать новые часы/попытки, не изменять серверный финализатор, оценки или историю. При смене предмета сбрасывать только временную поправку.
3. **Кеш загрузки**: обновить только версию загрузки \`exam-prep-live.js\` в \`exam-prep-api.js\` — без изменения маршрутов или логики основного API.

## Проверки в изолированной среде

- Реальное подписание JWT и HTTP→PostgREST→PostgreSQL 17: для P1/P5 Paper и Timed — ровно пять безопасных ключей, серверная дата впереди \`server_now\`, реальный frozen limit, другому ученику и анонимному запросу отказ. Non-timed — JSON \`null\`.
- Синтетический Chromium RU/UZ/EN: видимый обратный отсчёт, часы телефона на ±2 часа отличаются от сервера, \`time_expired\` завершает без выдуманных ответов, потеря подтверждения ответа не позволяет преждевременно завершить попытку.
- Структурный SQL-охранник в disposable PG17: формат, ограничения доступа, отсутствие внутренних полей.
- Все проверки должен пройти именно текущий SHA чернового PR; прежние успехи не переносить.
