# iClub AI Layer v2.1 — §§120–123. Сквозная локальная интеграция Edge → Auth shim → PostgreSQL

**2026-10-15. Технический GREEN, релизный статус OFF / NO-GO.**

## Доказанный путь

В отличие от прежнего моделирования ответов SQL, новый QA harness в GitHub Actions запускает **полноценную локальную PostgreSQL 16**. На ней в одной транзакции устанавливаются все 10 существующих SQL-черновиков `*_UNAPPLIED.sql` (включая 24 RPC), минимальная синтетическая модель реальных 89 полей и 23 безопасно воспроизводимых ограничения. На отдельных тестовых данных двух вымышленных учеников стартует отдельный локальный Node HTTP-шлюз, который:

- проверяет искусственные bearer-токены на маршруте `GET /auth/v1/user` и возвращает *только искусственную* проверенную личность;
- принимает только ограниченный список `POST /rest/v1/rpc/*`, требует особый synthetic service key и фактически вызывает соответствующую функцию в PostgreSQL в роли `service_role`; клиентский bearer напрямую не даёт доступ;
- поддерживает изолированные test-only действия отзыва enrolment/JWT, наступления protected assessment и переключения глобального kill switch; этих маршрутов нет в приложении или production Edge;
- не имеет соединений с настоящей Supabase, OpenAI, Vercel и платежными провайдерами.

Отдельный Deno тест по **реальному локальному HTTP** вызывает неизменные клиентские бизнес-модули `createSupabaseServices`, `makeContextCore`, `makeHttpHandler`. Это делает осмысленной проверку одной связки от Auth до SQL, а не двух несвязанных mock-тестов.

## Что ещё не выполнено

**Не утверждать полноту production готовности**. Текущие JWT состоят из тестовых строк, а `/auth/v1/user` эмулирован локальным Node-сервером. Это НЕ Supabase Auth и НЕ доказательство подписи действующих JWT. HTTP API совместим с формой RPC, но не является настоящий PostgREST. Не воспроизведены все 48 реальных ограничений, 43 индекса, 13 RLS-политик, четыре существующих триггера и внешние ключи к настоящей `auth.users`. Редакционно подписанные права на исходные материалы и опубликованные source bundle/version/hash отсутствуют. Provider/финансовый GO не дан. Действующий код приложения не использует этот автономный Edge.

Для будущего интегрированного Preview потребуются отдельное разрешение владельца на конкретную среду, code+security review 24 RPC и migration, действительный Auth и least privilege, актуальные источники/rights, полностью защищённый Core/Mathematics regression и возможность отката без пользовательских потерь. До этого **Global AI OFF / NO-GO**.

**Прямое подтверждение неизменности:** сравнение QA коммитов с базой §119 изменило только два QA исходника, один QA SQL fixture, GitHub Actions QA workflow и Master Plan. Ни `main`, ни production миграции, localStorage, Math Tutor, тарифы, данные учеников, Vercel, внешние сервисы и платные AI-вызовы не тронуты.
