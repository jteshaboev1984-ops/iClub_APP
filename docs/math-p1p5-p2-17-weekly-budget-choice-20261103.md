# P2-17 — сравнить оставшиеся часы с выделенным временем и принять рекомендацию одним нажатием

**Дата решения:** 03.11.2026. **База:** P2-14 Cambridge source-weighted average times, P2-15 timeline, P2-16 personal P1/P5 dates. Публичное включение остаётся отдельным решением.

## Экран ученика

Один блок Mathematics Exam Prep без новых страниц и сложных опросников:

- **Осталось примерно X часов** — исходя из 81 навыка P1/P5 и ориентиров Cambridge по разделам; коэффициенты частичного освоения являются предположениями iClub, не официальными часами самостоятельной подготовки Cambridge.
- **Мой план: Y ч/нед** — сколько ученик уже сам отвёл на Mathematics, берётся из реального Exam Prep профиля.
- **Ориентир: Z ч/нед** — для P1 и P5 вместе, если введены обе даты. Для одного выбранного экзамена — только его ориентир и подпись, что второй пока не учтён. Без дат рекомендация не появляется.
- При Y ≥ Z: спокойное «По текущему ориентиру выделенного времени хватает», без новых кнопок.
- При Y < Z: «Чтобы успеть, добавьте примерно N ч/нед». Если Z укладывается в уже указанный учеником **общий учебный недельный бюджет**, показать одну кнопку **«Выделить Z ч/нед»**.
- Если Z больше общего бюджета: информировать кратко, что нужен пересмотр общего времени в настройках; не предлагать недопустимую кнопку. Платформа **никогда не блокирует учебу** за нехватку часов.

**Один тап** на «Выделить» — это явное желание ученика изменить его недельный бюджет Mathematics. Не требуется школа, наставник или ещё одно подтверждение; это не автоматическое изменение и не платная функция.

## Как сохраняем без риска

[Серверная миграция draft PR #470](https://github.com/jteshaboev1984-ops/iClub_APP/blob/feature/math-p1p5-workload-registry-v1-20261103/supabase/migrations/20261103043000_exam_prep_student_accept_weekly_study_target_v1.sql): обогащает **существующий V2 owner-only ответ** текущими общими часами профиля и номером его ревизии. Не меняет версию контракта и не создаёт новых таблиц.

Только после реального нажатия вызывается `public.accept_my_exam_prep_timeline_weekly_target_safe_v1`. Внутри сервер получает uid через существующую Exam Prep Core access gate, блокирует строку своего профиля на время операции, проверяет неизменность исходного Mathematics-бюджета и ревизии, пересчитывает рекомендованные часы по **текущим навыкам и датам** (не доверяет присланному числу), запрещает значение выше общего недельного бюджета или 168 часов, запрещает повторное изменение при уже достаточном времени. Затем вызывает **существующий `public.save_exam_prep_exam_profile_v2`** — штатный путь обновления с журналом ревизий и сохранением прогресса — и возвращает актуальный расчёт.

В случае устаревшего значения, отказа в правах или превышения часов никакая запись не производится; на экране остаётся старое время и видимое сообщение об ошибке. Ранний/поздний экзамены не удваивают один общий Mathematics бюджет. Новые расчётные часы не являются гарантиями оценки.

## QA и условия

Трёхъязычные тексты (ru/uz/en), адаптивный дизайн 320/390/1440px, отдельные кейсы достаточного времени, нехватки, превышения общего бюджета, одного экзамена, устаревшей ревизии, повторного нажатия, анонимного доступа, ограничения 168 часов и сохранения всех исходных академических результатов.

Ветку main, production Supabase, Vercel, пользовательские данные, Practice/Tours, сертификаты и localStorage не менять. Оставить новый Timeline UI **выключенным по умолчанию** до отдельного решения по выпуску. В CI/тестах использовать только изолированную базу PG17 и синтетические браузерные экраны.

**Статус:** код P2-17 и тесты добавлены в draft; итоговый exact-SHA CI будет внесён после прохождения полного набора, не переносить статус P2-16 автоматически.
