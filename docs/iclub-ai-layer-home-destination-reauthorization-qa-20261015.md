# iClub AI Layer v2.1 — §109: проверка учебного назначения после Home claim (QA ONLY)

**Дата:** 2026-10-15. **Статус:** QA candidate, подтверждение полного CI требуется. **Релиз:** Global AI OFF / NO-GO.

## Что изменилось

§108 атомарно подтверждал только одноразовое Home-действие. §109 добавляет самостоятельный read-only серверный запрос `POST /qa/home/destination` **после** успешного `/qa/home/confirm` для исключительно временного, изолированного localhost HTTP→PostgreSQL. Запрос не разрешает переход к реальному экрану и не меняет академический прогресс.

В `qa/ai-layer-v21-p6-home-destination-proof.cjs`:

1. Сервер определяет owner по своему синтетическому Bearer-протоколу. Клиент не может передать userId, attemptId, sessionId или произвольный route.
2. SHA-256 одноразового токена находит *уже погашенное* разрешение. Непогашенное, подменённое, просроченное либо принадлежащее другому пользователю не принимается.
3. Сохранённый план повторно проверяется по HMAC, владельцу, версии Home-экрана, языку и точной выбранной паре action/subject. Академический id извлекается на сервере **из подписанного actionId**, а не из клиентского JSON.
4. Новый **единый read-only PostgreSQL MVCC SELECT** проверяет потраченный токен, существование конкретного учебного объекта и свежую полноту §107: source rights + source version/hash, текущие commercial subject rights, active slot, академический evidence, собственный Home контекст, expiry, global kill-switch. Данные разных пользователей не сливаются.
5. Сервер выдаёт только минимальный `targetScreen` из замкнутого набора: `practice-review`, `tour-review`, `subject-hub`, и `subjectKey`. Не выдаёт ID попытки/сессии, answer keys, grade, source hash или HMAC. Ответ всегда содержит `reviewOnly:true,releaseAllowed:false,navigationExecuted:false,progressChanged:false`.

Новые обязательные отрицательные тесты в `qa/ai-layer-v21-p6-home-pg-http.test.cjs`: непогашенный claim, чужой пользователь, подмена action/subject, попытка передать `objectId`, source revocation **после успешного одноразового подтверждения**, восстановление прав и повторная проверка. Проверяются все три учебных назначения в disposable PostgreSQL.

## Важная граница — НЕ настоящий переход ученика

Это **свежая авторизация выбранного учебного назначения до открытия**, а не доставка данных настоящего Practice/Tour, не роутинг действующего `app.js`, не разрешение открыть урок, не новая пользовательская сессия. Реальный экран меняет Home screen-context; после такого изменения **Home-контекст нельзя использовать как постоянный пропуск**. Для production требуется отдельная, подтверждённая серверная авторизация в каждом конечном API учебного экрана с собственным owner-bound context и реальными user/session/subject permissions. Одноразовое подтверждение Home не является доступом к произвольным учебным материалам. Содержимое ответа не даёт навигационного capability и не создаёт учебного evidence.

Реальная source-rights publication, production-compatible Edge/Supabase integration, публикация материалов, платный AI, protected integrated Preview и beta требуют отдельных проверок/разрешений. Запрещены новая Supabase branch, реальные миграции, реальные пользовательские записи, редактирование legacy Practice/Tour, тарифов, Mathematics Exam Prep, существующей AI-оболочки, локального прогресса и `main`.

**Проверка CI:** ожидается отдельный GitHub Actions run нового HEAD. До подтверждения результат не называется GREEN.
