# iClub APP — Written Learning in Universal Exam Prep

**Версия:** 1.0 · **Дата:** 22.10.2026 · **Статус:** согласованная продуктовая логика / реализация поэтапная.
**Владелец логики:** архитектор iClub. **Область:** Mathematics, Economics, Biology, Chemistry, Computer Science и будущие предметы.
**Редактируемая расширенная версия:** `iClub_Exam_Prep_Written_Learning_Contract_v1.0.docx` (рабочий артефакт).
**Изменения:** фиксировать версию, основание и результат QA ниже. Этот документ сохраняет принятые решения.

## 1. Принятое правило

**iClub готовит к экзамену, а не является экзаменатором.** Для письменного задания маршрут ученика:

**Задание → самостоятельное выполнение → «Критерии» / «Требования к ответу» (по желанию) → «Далее» по текущему плану.**

Ученик пишет работу самостоятельно вне приложения (на бумаге или удобным способом). Никаких обязательных вводов полного эссе, загрузок фотографий, отметок «разобрался», чек-листов, баллов самооценки, диалогов с AI или проверок ментором. «Далее» не зависит от открытия критериев.

Core не выводит «правильно», «проверено», «20/20», «мастерство подтверждено» для письменной работы, которую не проверял. Рекомендация обратиться к преподавателю или назначенному ментору — необязательная и ненавязчивая; без назначения ментора очередь/SLA не создаётся.

## 2. Три независимых уровня

| | Core | AI Tutor | Mentor Care |
|---|---|---|---|
| Задача | Управляет программой, заданиями, критериями, объективной проверкой и планом | Объясняет утверждённую теорию, смысл требований и установленные Core ошибки | Назначенный человек может проверять эссе и письменные решения |
| Эссе / произвольная письменная работа | Даёт задание/критерии, но не оценивает неполученный текст | Не оценивает работу и не выступает ментором | Может проверить только по активному назначению и условиям услуги |
| Академическая authority | Серверные детерминированные факты | Никаких баллов/mastery/изменений плана | Отдельное человеческое решение с журналом |
| Требуется для Core обучения | Да | Нет | Нет |

Права `core_access`, `ai_assist`, `mentor_care_entitled`, `mentor_assignment_active` определяются сервером отдельно. Не выводить права из названия тарифа в браузере. Коммерческий пакет может включать возможности, но не меняет академическую логику.

## 3. UI и поведение

Внутри существующего Exam Prep Host (визуально как Mathematics): название предмета/раздела/Paper, условие письменного задания, баллы/ориентир времени только где уместны, две функции — «Критерии» (или «Требования к ответу») и «Далее».

**«Критерии»:** открывает требуемые элементы ответа и применимую схему требований именно для вопроса/версии. Не показывает автоматически готовое эссе, полное решение или фиктивный персональный разбор. Подготовленный материал требует содержательного/языкового QA.

**«Далее»:** идемпотентный переход к следующему разрешённому планом шагу. Не создаёт событие академической правильности, не выставляет оценку, не добавляет AI/mentor задачу, не требует ввода текста.

**Пробный Paper с таймером:** общие экзаменационные требования могут быть доступны заранее. Специфичные критерии, раскрывающие ожидаемый ответ, доступны после финализации попытки. Полный Paper не получает искусственный общий балл, если письменные части никто не проверял.

**Рекомендация:** «Для проверки письменной работы обратитесь к преподавателю или назначенному ментору». Кнопка передачи работы активна только если сервис действительно реализован, entitlement действует и назначение активно. Отсутствие Mentor Care не должно показывать очередь ожидания.

Тексты:
- RU: «Критерии», «Требования к ответу», «Далее».
- UZ: «Baholash mezonlari», «Javobga qo‘yiladigan talablar», «Keyingi».
- EN: «Criteria», «Answer requirements», «Next».
Не показывать ученикам слова adapter, queue, лесенка и другие технические внутренние термины.

## 4. Данные / безопасность

Письменная практика может хранить `learner_id` (из auth), `program_key`, `program_version`, `paper_code`, `skill_key`, `task_id`, `task_version`, `plan_item_id`, `opened_at`, необязательное `criteria_opened_at`, `advanced_at` и идемпотентный ключ действия. Только если данные действительно нужны существующей логике плана.

**Не хранить по умолчанию:** само эссе, фото, self-mark, AI-score, mentor-job. «Далее» — факт перехода, не подтверждённая правильность, не оценка и не уровень освоения. Если текущий Mathematics RPC не поддерживает «Далее» без письменного ответа, нельзя подставлять фиктивный текст: нужен отдельный обратно-совместимый контракт.

Mentor Care при будущем подключении использует отдельный защищённый поток: активное назначение, явная отправка работы, приватный доступ, комментарий человека, сохранение истории. Не добавлять работы в очередь для не-назначенных учеников.

AI Tutor действует только в одобренных источниках и серверных разрешениях. AI=OFF, нет лимита или сбой модели не меняет работу Core. AI не оценивает эссе, не выдаёт grader score и не меняет подтверждённую успеваемость.

**Неприкосновенно:** Mathematics legacy runtime, Practice, Tours, существующие sessions/responses, оценки, user-subjects, localStorage, данные пользователей. Никаких миграций данных Mathematics в Economics.

## 5. Economics 9708 — первый предмет

Официальный Cambridge International Economics syllabus 2026–2028, версия 2: https://www.cambridgeinternational.org/Images/697423-2026-2028-syllabus.pdf

- P1: 30 MCQ / 60 минут / 30 баллов;
- P2: 120 минут / 60 баллов; A 20 (обязательный источник), B 20 (один из двух микро, структурированный вопрос), C 20 (один из двух макро, структурированный вопрос);
- P3: 30 MCQ / 75 минут / 30 баллов;
- P4: 120 минут / 60 баллов; A 20 (обязательный источник), B 20 (одно неструктурированное микроэссе), C 20 (одно неструктурированное макроэссе).

Черновой контент Phase 3 Batch 2 **EN-only**, ещё не утверждён; примерное распределение 8+12 для частей P2 НЕ объявлять официальной нормой. Для каждого письменного вопроса создать собственные требования, источник, syllabus/skill mapping, QA формулировок/языков/права использования. Нельзя подменять критерии пятью универсальными галочками.

Economics Exam Prep сейчас `draft` и `launch_enabled=false`. Не открывать ученикам до готовности runtime, QA и решения архитектора.

## 6. Этапы работ

| Очередность | Работа | Безопасная граница |
|---|---|---|
| 0 | Этот контракт, машинный JSON и автономный QA | Ни frontend, ни база не меняются |
| 1 | Инвентаризация действующих written/plan RPC Mathematics, схем и материалов Economics | READ-ONLY; определить минимальный отдельный способ перехода «Далее» |
| 2 | Предметные критерии и требования к оригинальным заданиям P2/P4 | Только закрытые версии после контентного и языкового QA |
| 3 | Core runtime: выдача задания → критерии → идемпотентное «Далее» | Отдельный безопасный Economics adapter, без изменения Math, флаг запуска OFF |
| 4 | Desktop/mobile RU/UZ/EN, auth/back/offline/resume, beta и rollback | Запуск только после проверки пользовательских данных |
| 5 | Необязательное Mentor Care для реально назначенных учеников | Ни одному не-назначенному learner не создавать очередь |

## 7. Критерии приёмки

1. Без AI/Mentor ученик может открыть written task, по желанию посмотреть критерии и перейти к следующему шагу.
2. Переход не требует эссе в textarea, photo, самооценки или дополнительного диалога.
3. Переход не выдаёт оценки, не повышает mastery, не создаёт mentor queue или AI judgement.
4. Двойное «Далее» не создаёт второе продвижение; при offline нельзя ложно подтверждать серверное сохранение.
5. AI только объясняет. Менторная проверка возможна лишь с активными правами и назначением.
6. RU/UZ/EN и доступность мобильной навигации проверены, критерии соответствуют вопросу.
7. Economics не включён до полного QA; Mathematics, Practice, Tours и пользовательские данные сохранены.
