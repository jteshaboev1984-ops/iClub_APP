# iClub AI Layer v2.1 — Home final delivery, TTL and safe choices (§104–§106)

**Дата:** 2026-10-15. **Среда:** только изолированный QA + одноразовая PostgreSQL в GitHub Actions. **Real Global AI:** NO-GO.

## §104 — Отзыв прав после выбора, но до HTTP-ответа

Подписать Home plan недостаточно: тариф, зарегистрированный выбор предмета, учебное evidence или редакционное право на источник могут быть отозваны за время отдельных асинхронных проверок. Дополнительный модуль `qa/ai-layer-v21-p6-home-delivery-gate.cjs` проверяет перед возвратом браузеру:

- HMAC подпись плана; его владельца, revision, 30-секундный TTL, разрешённую политику;
- точное соответствие результата выбранного приоритета подписанным действиям — без подмены subject/action;
- текущие полный server-scan и owner-bound Home screen;
- отдельно коммерческое подтверждение конкретного intent + предмета, академическое evidence, source rights/content/hash/version;
- повторную проверку после ожиданий и последний повторный screen/scan с проверкой истечения TTL.

`qa/ai-layer-v21-p6-home-pg-http-gateway.cjs` теперь выполняет этот gate непосредственно до успешного HTTP 200. Отрицательные тесты `qa/ai-layer-v21-p6-home-delivery-gate.test.cjs` и `qa/ai-layer-v21-p6-home-pg-http.test.cjs` моделируют *отзыв после выбора и до отправки* прямо в одноразовых PostgreSQL-таблицах: снятие тарифного `ai_generation_entitled`, отозванные source rights и смену server-screen revision; результат должен быть отказом без утечки данных.

**Фундаментальное ограничение:** последовательные read-only запросы даже с последней перепроверкой НЕ составляют единую serializable DB-транзакцию. Между самым последним чтением и отправкой может измениться состояние. Для реального выпуска потребуется автономный owner-bound атомарный read/compare в одной доверенной серверной транзакции, актуальные source/entitlement revision и повторное подтверждение при фактическом переходе. QA-тест нельзя выдавать за доказательство такой атомарности.

## §105 — Internal evidence IDs остаются только на сервере

Ранее равноприоритетные предложения возвращали `candidateActionIds`, включавшие служебные номера Evidence/Practice/Tour. Теперь `validateBeforeHomeDelivery` сопоставляет внутренние IDs и подписанный план **только внутри сервера**, а наружу отдаёт ровно `choices:[{actionCode,subjectKey}]` для предметов с подтверждённым доступом. Нет полей с session ID, score, answer key, sourceHash, HMAC/JWT или внутренними токенами. Отрицательные тесты проверяют целостность множества предложений и невозможность вставить чужой/удалённый вариант.

## §106 — UI на трёх языках и срок рекомендации

Отдельный локальный `qa/preview_v21/home-pg-local.html` использует тексты названий предметов, скопированные **без изменений** из действующего `i18n.js`: RU, UZ, EN. При равном приоритете показывает все проверенные предметы (не выбирает предмет автоматически и не показывает внутренние IDs). Статический JSON названий проверяется тестом `qa/ai-layer-v21-p6-home-subject-labels.test.cjs` против текущих записей в `i18n.js`. Список выводится через DOM `textContent`, а не `innerHTML`.

Сервер добавляет `expiresAtMs` в минимальный ответ. UI автоматически удаляет устаревшую рекомендацию по TTL; при смене языка, раздела и выходе сбрасывает список и ответы. Native Chromium `qa/ai-layer-v21-p6-home-pg-chromium.cjs` проверяет RU 320×568, UZ 390×844, EN 1366×768, наличие всех равноприоритетных названий и отсутствие внешних сетевых запросов. UI представляет только локальную синтетическую демонстрацию, не product release.

## Границы неизменности

- Ни один из этих QA-модулей не подключён к production `app.js`, Mathematics Tutor или реально опубликованному Global AI Edge.
- Нет новой Supabase-ветки, новых расходов, production записей и чтения записей реальных учеников.
- Действующие тарифы, i18n, localStorage/прогресс и production-домены не изменяются.
- Product-approved 18 общих инструкций не равны независимой editorial/source rights публикации. Synthetic rights flags не являются реальными лицензиями.
- QA-to-QA PR временный, **НЕ сливать в main**, закрыть после подтверждённого полного CI.
- Конечная интеграция с сервером и реальными разрешениями ученика, источниками и атомарностью по-прежнему требует отдельного release GO.

**CI:** результат §106 будет занесён в Master Plan после получения фактического статуса, без предварительных заявлений GREEN.
