# Exam Prep: повторное обучение на существующих заданиях — решение владельца от 21.09.2026

**Статус: утверждена продуктовая логика, реализация и выпуск НЕ утверждены.** Документ заменяет прежнее требование производить новые учебные комплекты для 81 навыка. Никакой SQL из черновика не устанавливать, PR #121 не объединять, функцию не включать без отдельного разрешения.

## Проверенная исходная ситуация

- P1: 45 навыков, P5: 36. Для каждого опубликован ровно один учебный комплект, альтернативных комплектов нет.
- У ученика P1-CIR-01 уже было девять завершённых попыток одного комплекта. Сохранённые ответы и незавершённая письменная работа другого ученика не трогать.
- В действующей логике исправления ошибка закрывается только после выполнения учебной работы (минимум 3/3 правильных объективных ответа + сохранённое письменное решение) И успешной **отдельной отложенной проверки** на защищённых вопросах. Сам повтор учебного комплекта не является новой независимой проверкой знаний.

## Обязательное поведение

1. Сначала возобновлять существующую активную попытку и первый вопрос без сохранённого ответа, включая письменное решение. Не создавать новую сессию при двойном нажатии, смене устройства или неопределённом результате сети.
2. Первое прохождение опубликованного учебного комплекта остаётся обычным обучением. Если ученик уже видел эти вопросы и **не выполнил требуемую учебную работу**, разрешить ему осознанно пройти тот же комплект заново. Показать понятное предупреждение перед началом: «Вы уже видели эти вопросы. Повторите их, чтобы разобраться в ошибках. Это учебное повторение, а не новая проверка знаний. Ваши прежние ответы сохранены». Аналогичный корректный текст RU/UZ Latin/EN.
3. Если работа уже выполнена, не предлагать её повторный запуск ради дополнительных баллов. Для незакрытой ошибки показать ожидание отдельной отложенной проверки, а для выполненной цели — следующий действующий шаг.
4. Повтор сохранить отдельной новой попыткой, не изменяя прошлые ответы, оценки, `assessment_id` и опубликованные задания. Метка `learning_review` и `academic_credit=false` должны исключать повторные задания из *новых независимых* подтверждений покрытия программы, уровня владения, готовности и исторической статистики впервые изученных тем. Сохранённое письменное решение нельзя выдавать за проверенное ментором.
5. Если это работа над ошибкой, её факт выполнения может переводить ошибку к ожиданию отложенной проверки только по прежнему правилу 3/3 + письменное решение; сама ошибка считается закрытой исключительно после свежей отложенной проверки. Потребуется согласовать обработчик коррекции и отчёт о недельных целях с меткой повторения: они не должны повышать mastery или ошибочно считать повтор отдельной новой проверкой.
6. P1 и P5 полностью независимы. Нельзя брать вопросы из диагностики, retest, mixed, timed или защищённого резерва ради обхода отсутствия новых учебных комплектов. Нельзя изменять нормативные пороги или автоматически перестраивать недельный/экзаменационный план.
7. Если нет достоверных сведений, что предыдущее прохождение неуспешно, не угадывать статус и не создавать повторную попытку. Показывать прежние результаты/доступные шаги, не обещая новую оценку. Следующий шаг — только в существующем недельном плане.

## Проверки перед выпуском

На полностью искусственных данных в отдельном PostgreSQL и браузере проверить: впервые видит → обычная попытка; 2/3 + письменная работа → явно помеченный повтор того же комплекта; 3/3 + письменная работа → отсутствие бесконечного повторения; исправление → только свежая отложенная проверка закрывает ошибку; сохранение исторических попыток, восстановление активного письменного ответа, двойной клик и два устройства, истечение недели, RU/UZ/EN и мобильный/компьютер, отсутствие влияния на Practice/Tours/сертификаты/рейтинги.

**Текущий код не соответствует этой политике полностью:** прежние `content_exhausted` проверки запрещают повтор, а существующие обработчики академических результатов нельзя менять вслепую. Полный выпуск блокируется до сквозной проверки обработки метки повторения, проблемы истории Practice #125 и отдельных подтверждений владельца для SQL, merge/deploy и включения.
