## Source implementation in this Draft

1. **Strictly private bucket** `iclub-math-s2-private` is defined in **uninstalled** SQL. Never change `books` or its public users. No learner insert/update/delete to `storage.objects`, no publicly guessable Storage URL as an authorization mechanism, no use of `service_role` in the browser. Use user JWT with `storage.from(bucket).download(path)` and RLS **only** for `object.get_authenticated`. No listing and no signed-link capability.
2. **Server authority** is the existing owned, unfinalized `tour_session_runtime_v4` snapshot and its matching `tour_attempts` row. The private asset manifest is service-role/editorial-only and must be bound to one actual question/approved object path/checksum. RLS checks `auth.uid()`, S2 Mathematics, matched attempt/tour and not finalized. Rights are checked on every fresh authenticated download. Do not grant unauthenticated, nonmember, wrong-user or finalized attempts access.
3. **Pre-start RPC** returns **only** eligible/ready + counts after all required approved image objects have been uploaded. It returns no private path, question, key, answer options, order, image or public URL. It cannot promise that the user's current network can fetch an asset.
4. **After start** the client asks the server for image paths belonging to its same issued attempt, downloads each image with authenticated Storage and validates MIME, size and decoding; only local `blob:` URLs created from the authenticated bytes reach the Tour renderer. Legacy public URLs from `questions.image_url` are overwritten, never used as fallback.
5. **Retry on bad network**: signed owner-scoped `get_math_s2_resume_attempt_v1` detects the unfinished attempt **before** calling the existing start function. A failed private download does not call finalize or issue a second attempt. UI tells the learner the server attempt already exists and can be resumed. Only finalized attempt data stays finalized; no resets of answers/rating/certificates.
6. **Cached S2 clients** cannot handle new protected images. The separately guarded preflight v4 **must fail before starting** for S2 while S1/Chemistry/other subjects still use original preflight and preload. Old clients must reload; do not allow them to consume a Tour attempt with images missing. The source candidate #641, which deliberately returned public image URLs for legacy preload, must NOT be deployed alongside private-image protection.
