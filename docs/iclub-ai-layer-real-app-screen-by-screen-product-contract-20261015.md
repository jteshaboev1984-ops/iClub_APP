# iClub AI v2.1 — реальное приложение: экранная логика и условие Vercel Preview

**Статус: ПРОЕКТ ПРОДУКТОВОЙ ЛОГИКИ ДЛЯ ВИЗУАЛЬНОЙ ПРИЁМКИ.** 15 октября 2026. Основа — `docs/iclub-ai-layer-master-plan-v2.1.md` (44 решения), фактические `index.html` и `global-ai-ui.js`, существующие Mathematics Exam Prep/Core. Этот документ **не** разрешает выпуск, затраты, источник или работу с данными учеников.

## 1. Исправление прежней ошибки

Отдельные `qa/ai-layer-v21-protected-preview/`, `qa/ai-layer-v21-app-look-preview/`, `qa/preview_v21/` полезны лишь как автономные QA-фикстуры. Их автономная главная, «пример ученика», искусственные оценки и собственные маршруты **не могут приниматься как UX приложения**, даже при копировании CSS. Пользователь принимает исключительно **действительный iClub APP в защищённом Vercel Preview**: оригинальные `index.html`, `app.js`, `style.css`, `i18n.js`, `visual/`, `exam-prep/`, четыре настоящие вкладки и естественные переходы.

**Preview без искусственной регистрации и ответов в production Supabase.** Исходный Preview с реальной Supabase может писать в production. Поэтому интерактивную AI-демонстрацию надо подключить как изолированный QA-only слой к реально работающему shell, с подменой **только нового AI backend** и без изменения существующего учебного состояния. При отсутствии безопасной тестовой сессии настоящие Practice/Tour/Exam Prep нельзя проходить как фиктивный ученик. Нельзя выдавать статическое демо за live APP.

## 2. Один AI, две области, одна понятная панель

- **iClub AI** — общие вопросы о разделах iClub, существующих возможностях, доступных направлениях, подтверждённых следующих шагах. Это не академический совет наугад.
- **iClub AI Tutor** — контекстная учебная помощь по конкретному *подтверждённому* предмету, уроку, навыку или завершённой ошибке. Один и тот же знак и панель, но заголовок/подзаголовок и быстрые запросы меняются по экрану.
- Правило **контекст прежде генерации**: браузер может подсказать текущее название, но server-proof всегда сам проверяет user, current-screen, учебный object ID, предмет, locale, source readiness и protected status. Нет proof → общая помощь без доступа к учебным данным либо честное «В разработке».
- Короткий первый ответ: 2–5 небольших абзацев, при необходимости формула/пошаговое рассуждение, далее действия «Объясни проще» / «Приведи пример» / «Что повторить». Нельзя выдавать ответ как новую оценку или итоговую аттестацию.
- Плавающий AI-знак **один**; в правом нижнем углу **выше** четырёхвкладочной навигации и safe-area. Контекстные кнопки только в подтверждённых местах. Mobile bottom sheet 70–80% высоты, расширение до full screen; desktop компактная панель. При смене раздела панель сворачивается и очищает право старого контекста; отдельные сессионные чаты General/subject не смешиваются.
- Первое открытие — краткая понятная памятка: что AI умеет, что ничего не меняет в оценках, какие данные видит и что ответы могут быть неточными. **Один раз за текущую сессию**, без создания скрытых пользовательских данных.

## 3. Реальный путь учеников: экран за экраном

Фактическая разметка `index.html` содержит top-level `view-home`, `view-courses`, `view-ratings`, `view-profile` и внутренние `courses-*` экраны. Ниже правила показа сформулированы для каждого реально существующего экрана. `Разрешено` означает **целевое поведение после readiness и выпуска**, а не сегодняшнюю активность AI.

### Четыре визуальных состояния AI, которые обязательны для приёмки

**1. Общая помощь.** Маленький фирменный знак справа над нижним меню; при нажатии — аккуратная панель «iClub AI», один короткий текст о доступных действиях, 2–3 уместных вопроса и поле ввода. Никакой искусственной оценки/процента.

**2. Предметный Tutor.** Тот же знак; заголовок «iClub AI Tutor», ниже настоящий предмет/раздел, контекстные чипы из разрешённого источника. Отдельный чат предмета, не смешан с General. Неготовая тема честно сообщает статус только по нажатию.

**3. Завершённая ошибка.** На реальном экране результатов или разбора находится маленькая понятная кнопка «Объяснить ошибку». Открывается та же панель, в шапке уточняется вопрос/тема; сразу виден короткий подготовленный ответ при готовом source. Ученик не переписывает оценку.

**4. Защищённая проверка.** Ни значка, ни панели, ни доступного prompt при активной Practice/Tour/Exam Prep assessment. После завершения экран сам возвращает иконку только после подтверждения права; устаревший ответ из предыдущего экрана не показывать.

### 4. UI-переходы, которые должны работать в настоящем Preview

`Home → Study (реальная вкладка) → subject-hub → lessons → разрешённая тема → Tutor → Back`.

`Practice start → active quiz (AI полностью скрыт) → finalized result → review → «Объяснить ошибку» → Tutor → Home`. Для Preview, подключённого к production, не отправлять искусственный ответ в действующую БД: использовать синтетический локальный экранный proof или специальную no-write fixture под рабочей навигацией с визуально помеченным тестовым контекстом.

`Tours → rules → active Tour (AI отсутствует) → только после официального архива → Tour review → AI error explanation`.

`Mathematics → Exam Prep → P1 / P5 отдельно → доступный theory/skill view → существующий Tutor без нового списания → assessment blackout`.

`Profile → объяснить подтверждённый прогресс → Home`. Никаких новых student DB rows.

### 5. Права, источники, экономика и сбои

- Сервер каждый раз переоценивает `surface×subject×topic×locale×feature`, owner, finalized/archive, source version/right/hash, тариф и protected state. Всё fail-closed; `service_role` не заменяет owner check.
- AI не отвечает «по памяти» за закрытый/неподтверждённый источник. Без права, версии, точного предмета или готового языка показать «В разработке» и допустимую общую справку.
- Ответы-карточки и генерация идут через один серверный учёт после отдельного финансового GO. Тестовая система 1:3/3-9-14 из Master Plan **не является утверждённым коммерческим тарифом**. Визуал не показывает внутренние доли.
- Если остались только готовые объяснения, пользователь видит понятное предложение более простого действия, не сброс прогресса. Падение провайдера → готовый ответ с корректным контекстом либо честный отказ без списания.
- Смена экрана отзывает прошлый context handle, закрывает панель, сохраняет не более сессионной истории внутри конкретного чата. Logout, отказ права и изменение личности уничтожают доступ к старой истории. Никаких долговременных transcript в localStorage.
- AI на экране служит помощником, а не автопроходчиком: не сдаёт вопросы, не меняет lesson completion, progress, placement, mastery, readiness, mark, рейтинг, сертификат или mentor judgement.

## 6. Обязательные условия **настоящего** Vercel Preview

Реальный Vercel-проект `i-club-app` существует. Уже есть действующие защищённые Preview deployments других QA-веток и отдельный статический P6 AI Preview. Последний **не годится** на визуальную приёмку. Правильный Preview должен быть новой commit-pinned **Git-source сборкой настоящего приложения**, а не `files:[{file:"index.html",data:"..."}]` со сторонней подделкой.

Для безопасности:
1. Сохраняем оригинальную product shell и real route engine (без замены `app.js` на mock). Изменения AI только **отдельные QA source overlays** и ограниченное подключение к действующим view containers.
2. GitHub source ref и точный commit, preview target (`target=null`), отдельный immutable URL; не применять `main`/production target, domain alias или environment promotion.
3. **Безопасная сеть:** если этот Vercel-проект наследует переменные/ключи действующей Supabase, новые QA AI calls должны быть заблокированы по умолчанию, browser mock не должен вызывать live server functions; не создавать/редактировать users, academic progress, subscriptions, payments и certificates. В идеале отдельная одобренная isolation config; без доказательства блокировки никаких практических user interactions с реальными сервисами.
4. Проверить Vercel authentication/SSO до отправки ссылки владельцу, не публиковать незапароленный учебный Preview с изменённым поведением.
5. Проверить реальные CSS/JS/asset network, адаптив 320/390/desktop, RU/UZ/EN, natural transitions; AI blackout / no backend writes в runtime.
6. Только после безопасности выполнить **один** защищённый Vercel Preview deploy, зафиксировать фактический deployment ID/READY, ссылку и сравнение с production UI.
7. Для настоящей AI beta отдельно всё равно необходимы approved rights/source publication, independent Supabase Auth/RPC integration, лимиты и расходы и явный GO архитектора.

**Текущий статус:** экранная модель согласована с Master Plan как QA-кандидат; визуальная и инфраструктурная приёмка не выполнена. Релиз Global AI по-прежнему OFF / NO-GO.
