# Mathematics P1/P5 — P2-10. Результаты → оставшиеся действия → проверяемое время

**Версия:** 03.11.2026. **Issue:** [#450](https://github.com/jteshaboev1984-ops/iClub_APP/issues/450). **Код:** [draft PR #470](https://github.com/jteshaboev1984-ops/iClub_APP/pull/470). **Статус:** технический E2E пройден, академические нормы времени не утверждены, публичный релиз NO_GO.

## 1. Решение архитектора

Нагрузка определяется реальным подтверждённым прогрессом ученика по 81 навыку, а не числом неправильных ответов и не одинаковыми часами для всех. Учитывается каждое уникальное оставшееся действие по конкретному навыку. Пять ошибок на одном навыке не означают пять полных уроков. После подтверждённого исправления ранее допущенные ошибки перестают увеличивать будущую нагрузку. Непроверенный навык остаётся неизвестным и получает диагностическую проверку, а не статус слабого.

## 2. Типы возможных действий

| Код | Смысл |
| --- | --- |
| targeted_check | Проверка навыка без объективных данных, не полное переобучение |
| correction | Исправление незакрытой ошибки по навыку, без умножения на число старых ответов |
| targeted_practice | Адресная практика при неподтверждённом освоении |
| delayed_retest | Отсроченная проверка сохранения результата |
| mixed_transfer | Проверка применения навыка в новом смешанном контексте |
| written_work_unscored | Письменная работа как факт обучения, без автоматического выставления баллов |

**81 × 6 = 486** — это варианты действий в закрытом реестре, **не 486 назначенных занятий**. В персональном плане учитываются только действия из актуального серверного состояния. P1 и P5 имеют независимые компетенции и экзаменационные даты, но общий учебный бюджет Mathematics.

## 3. Конкретная реализация

[Новая миграция P2-10](https://github.com/jteshaboev1984-ops/iClub_APP/blob/feature/math-p1p5-workload-registry-v1-20261103/supabase/migrations/20261103037000_exam_prep_p1p5_action_time_norm_registry_v1.sql) создаёт отдельный закрытый от прямого доступа учеников источник для 486 возможных сочетаний навыка/действия, начально все со статусом unreviewed и отсутствующими числовыми минутами. Изменение статуса на approved требует версию методики, содержательное объяснение, источник наблюдений, два разных проверяющих и даты проверки. Оно само по себе не заменяет действительную независимую академическую приёмку.

Внутренний серверный вычислитель складывает минимальное/максимальное время **только реально ожидающих действий** и только при полном их покрытии утверждёнными интервальными нормами. Отсутствие одной нормы обнуляет числовой результат соответствующего компонента в смысле NULL, а не заменяет её нулевым временем. Общие prerequisites, отдельное повторение и полные пробные экзамены требуют самостоятельного обоснования, поэтому это ещё не полные часы подготовки.

Защищённый owner-only API показывает пока только число ожидающих действий и покрытие нормативами. Он намеренно **всегда** возвращает NULL для персональных минут и рекомендуемых часов и не включает кнопку принятия, даже если внутренний искусственный тест успешно складывает числа. UI приложения новый API не вызывает; расписание и прогресс не меняются.
